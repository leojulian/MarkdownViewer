# WebView 历史导航与文档树选择同步设计

**项目**：`D:\CodeHere\practise\MarkdownViewer`
**分支**：Git `main`
**日期**：2026-08-10
**状态**：已批准

## 1. 目标

用户在当前 workspace 内通过 Markdown 链接从文档 A 跳转到文档 B 后，使用鼠标前进、后退按键切换 WebView2 浏览历史时，应用外部状态必须与实际显示的历史页面一致：

- 窗口 `Title`；
- `StatusText`；
- `FilePathText`；
- 文档树当前选择；
- 收藏按钮状态；
- `_currentFilePath`。

文档树同步必须展开目标节点的父目录并将目标节点滚动到可见区域，但不能再次加载 Markdown、不能产生新的 WebView2 历史记录。

## 2. 非目标

- 不建立独立于 WebView2 的应用导航栈。
- 不接管或重新映射鼠标前进、后退按键。
- 不因历史目标失效而重建文档树、切换 workspace 或打开新进程。
- 不改变普通树点击、收藏点击、文件监控或 Markdown 链接路由的既有行为。
- 不修改历史记录、收藏或配置文件格式。

## 3. 已确认行为边界

历史页面只有同时满足以下条件时，才允许同步应用外部状态：

1. 页面包含有效的 MarkdownViewer 文档路径元数据；
2. 路径对应的文件仍然存在；
3. 应用仍处于 workspace 模式；
4. 文件仍位于当前 workspace 内；
5. 文档树中能够定位对应文件节点。

任一条件不满足时，文档树选择、`Title`、状态栏、路径、收藏状态和 `_currentFilePath` 全部保持不变。页面本身由 WebView2 历史机制决定，本设计不强制把页面导航回原文档。

## 4. 方案

采用集中式原子同步，不重建文档树，也不自建导航栈。

### 4.1 页面身份

每个由 `WrapHtml` 生成的 Markdown 页面在 `<head>` 中携带文件路径元数据。路径写入和脚本结果解析继续由可独立测试的 `DocumentMetadataService` 负责，以正确处理中文、空格、引号和其他需要 HTML/JSON 编码的字符。

空页面、文件不可用页面等没有真实 Markdown 文件来源的页面不携带有效文档路径。

### 4.2 导航完成后的同步

`WebView_NavigationCompleted` 仅在导航成功且该事件属于当前最新导航时读取页面元数据，避免快速连续前进、后退时由过期完成事件覆盖新状态。

同步分为两个阶段：

1. **只读验证阶段**
   - 读取并解析页面文档路径；
   - 判断路径是否与当前文件不同；
   - 验证文件存在、属于当前 workspace；
   - 在文档树中查找目标节点，但不改变选择或其他 UI 状态。
2. **提交阶段**
   - 展开目标节点的父目录；
   - 在抑制树选择加载事件的情况下选中目标节点并滚动到可见区域；
   - 更新 `_currentFilePath`、`FilePathText`、`StatusText`、`Title` 和收藏按钮。

只有只读验证阶段全部成功后才能进入提交阶段。不得先更新标题或 `_currentFilePath`，再尝试选择树节点。

### 4.3 文档树职责

现有 `SelectFileInTree` 同时承担“查找节点”“改变选择”和“可选加载文件”三个职责。为支持原子同步，实施时应提供不产生副作用的节点查找入口，导航同步先取得目标 `TreeViewItem`，再执行选择更新。

普通调用仍可保留现有 `SelectFileInTree(filePath, loadFile)` 行为；历史导航同步必须使用 `loadFile: false` 等价路径，确保 `SelectedItemChanged` 不调用 `LoadMarkdownFile`。

## 5. 状态流

```text
Markdown 链接 A -> B
        |
        v
WebView2 形成页面历史 A, B
        |
鼠标后退/前进
        |
        v
NavigationCompleted（仅最新且成功）
        |
读取页面文件元数据
        |
验证文件 + workspace + 树节点
      /   \
   失败     成功
    |        |
保持 UI   原子更新树选择和文档状态
```

## 6. 失败处理

- 元数据缺失、JSON 解析失败或脚本执行异常：保持全部外部状态不变。
- 文件已删除或移动：保持全部外部状态不变。
- 文件位于当前 workspace 外：保持全部外部状态不变。
- 文档树找不到节点：保持全部外部状态不变，不自动刷新树。
- 导航失败或完成事件已过期：不进行同步。
- 树选择更新期间必须恢复事件抑制标记；即使发生异常，也不能让后续用户树点击永久失效。

## 7. 验证设计

### 7.1 自动化测试

- 页面路径元数据能够保留中文、空格和引号。
- 空白或非法脚本结果不会产生文档路径。
- 若将导航同步的资格判断提取为非 UI 服务或辅助逻辑，应覆盖：文件存在且在 workspace 内、workspace 外、文件缺失和路径无效场景。

WPF `TreeViewItem` 与 WebView2 浏览历史交互不适合仅靠当前 xUnit 测试项目完整验证，因此必须补充真实应用验证。

### 7.2 综合验证

在 workspace 中准备互相链接的 `A.md`、`B.md`，执行：

1. 打开 A，点击 Markdown 链接进入 B；确认 B 的页面、树选择、标题、状态、路径和收藏状态一致。
2. 按鼠标后退键；确认页面回到 A，树选中 A，并同步更新标题、状态、路径和收藏状态。
3. 按鼠标前进键；确认全部状态回到 B。
4. 连续快速执行前进、后退；确认最终状态对应最后显示的页面，不出现延迟反向覆盖。
5. 导航到 B 后使 A 删除、移动出 workspace 或从树中不可定位，再后退；确认树选择、标题、状态、路径、收藏状态和 `_currentFilePath` 保持 B 的状态不变。
6. 确认前进、后退同步没有再次调用 `LoadMarkdownFile`，没有向浏览历史追加重复页面。

### 7.3 项目验证命令

```powershell
dotnet build MarkdownViewer.sln -c Release
dotnet test MarkdownViewer.sln -c Release
```

## 9. 兼容性与风险

- 继续使用 WebView2 原生历史，不改变鼠标侧键和浏览器导航语义。
- 不改变 workspace 边界规则，也不允许历史页面绕过当前 workspace 打开文件。
- 最大风险是异步导航完成事件与 WPF 树选择事件互相触发；通过最新导航编号、先验证后提交和选择事件抑制控制。
- 当前工作区已存在与页面元数据同步相关的未提交改动；实施时必须基于现有差异增量修改，不覆盖用户已有代码。
